# github-tasks — задачи на GitHub для Claude Code

Плагин для Claude Code, который ведёт задачи проекта так, как их ведут нормальные команды:
задача в GitHub Issues → своя ветка → PR → независимая приёмка → слияние. Только делают
это агенты, а ты смотришь и решаешь.

Когда в одном репозитории работают три-четыре сессии Claude сразу, начинается бардак: две
берут одну и ту же задачу, кто-то коммитит чужие файлы через `git add -A`, а свою же работу
агент «проверяет» и сам принимает. Знакомо? Вот это плагин и лечит.

## Что ты получаешь

- **Задачу не возьмут двое.** Сессии захватывают задачу через комментарий-заявку: из
  одновременных побеждает ровно одна, вторая получает «занято» и идёт за другой.
- **У каждой сессии своя рабочая копия** (`.claude/worktrees/issue-N`) — агенты не правят
  одни и те же файлы на диске.
- **Свою работу никто не принимает.** Проверяет отдельный агент-приёмщик: сам запускает
  проверки, по каждому критерию ставит «выполнен / не выполнен», пишет вердикт в PR. Править
  код он не может — это держит хук (проверка, которую Claude Code запускает перед каждой
  командой агента и может её запретить).
- **Задача закрывается слиянием PR**, а не руками «вроде готово».
- **Защита от типичных бед:** хуки не дают сделать `git add -A` (захватить в коммит все
  файлы подряд, включая чужие), force push (перезаписать историю на GitHub) и коммит прямо
  в `main`.
- **Статус — одной меткой** на задаче. Доски нет: вместо неё ссылки-фильтры «на приёмке»,
  «ждёт моего решения», «блокеры» — в README твоего проекта.

## Что нужно

- Claude Code.
- `gh` — GitHub CLI, вход выполнен (`gh auth login`).
- `git` и `bash` — на macOS и Linux они уже есть. На Windows плагин пока не проверялся.
- `python3` или `node` — обычно один из них уже стоит. Без них плагин не работает:
  скрипты не прочитают файл настроек, а хуки не разберут команды и **молча перестанут
  защищать**. Проверить: `python3 --version` или `node --version`.

## Установка — две команды

В Claude Code:

```
/plugin marketplace add sanya8923/VibeBusiness
/plugin install github-tasks@vibe-business
```

Перезапусти Claude Code. Всё, плагин стоит. В проектах без его настроек он молчит — хуки
ничего не трогают, пока ты сам не включишь процесс в репозитории.

## Включить в проекте

Открой Claude Code в своём репозитории и напиши:

> настрой задачи на GitHub

Плагин посмотрит, какие метки и проверки уже есть в проекте, покажет, что собирается
сделать, и после твоего «ок»:

- сразу заведёт на GitHub метки статуса;
- откроет PR с файлами: настройки `.claude/github-tasks.json`, шаблон задачи и ссылки-фильтры
  в README.

Слей этот PR на GitHub — процесс включён. Потом верни свою копию на основную ветку:
`git switch main && git pull` — после настройки она остаётся на ветке `setup-github-tasks`.

## Первая задача по шагам

1. **Поставить:** «поставь задачу: добавить страницу контактов». Агент поищет дубли, соберёт
   план, покажет тебе. Одобрил — задача появится в Issues со статусом `ready`.
2. **Сделать и принять одним заходом:** «проведи задачу #12 целиком». Агент возьмёт задачу,
   сделает её в своей ветке, откроет PR, позовёт приёмщика. Если приёмщик вернёт — исправит
   и отдаст ему же. Принято — PR сольётся, задача закроется.
3. **Или по отдельности:** «возьми задачу #12» в одной сессии и «прими задачу #12» в другой.
   Так видно, что исполнитель и приёмщик — разные.

Что ещё умеет — просто спрашивай словами:

| Скажи | Что будет |
|---|---|
| «что с задачами» | короткая сводка: в работе, на приёмке, блокеры, что ждёт тебя |
| «передай задачу», «закругляемся» | состояние задачи — комментарием в неё, коммит, push |
| «перебери задачи», «что режем» | разбор очереди по реальной скорости: делаем / режем / переносим |
| «можно выкладывать?» | проверка перед релизом: закрыты ли задачи вехи (вехой на GitHub называют группу задач к одному выпуску), нет ли блокеров, прошли ли автоматические проверки на GitHub, не попали ли в код ключи и пароли |

## Несколько сессий одновременно

Открой несколько окон Claude Code в одном репозитории и дай каждому свою задачу —
«проведи задачу #12 целиком», «проведи задачу #15 целиком». Если две сессии попросить одну и
ту же задачу, возьмёт одна, вторая скажет «занято».

## Как смотреть задачи

В README проекта после настройки появится блок «Задачи проекта» со ссылками:
на приёмке, ждёт моего решения, блокеры, в работе, готово к работе, а ещё черновики —
задачи без статуса. Это обычные поиски
GitHub по меткам — сохрани в закладки.

## Честно об ограничениях

- **Хуки — защита от случайной ошибки, а не от злого умысла.** Они разбирают команды
  оболочки и ловят обычные формы записи. Агент, который нарочно захочет обойти правило через
  `eval` или код внутри `python -c`, сможет. Список того, что не ловится, — в шапках
  `hooks/guard-git.sh` и `hooks/guard-readonly.sh`.
- **Все сессии под одним аккаунтом GitHub** различаются по комментарию-заявке, а не по
  исполнителю: исполнителем у всех будешь ты.
- **Защиту ветки `main` настройками GitHub плагин не ставит** — на бесплатном тарифе для
  закрытых репозиториев её нет. Хуки закрывают это для сессий Claude, но не для людей.

## Частые вопросы

**Плагин ничего не делает.** Проверь, что в корне проекта есть `.claude/github-tasks.json` —
без него процесс выключен. Нет — скажи «настрой задачи на GitHub».

**«для чтения .claude/github-tasks.json нужен python3 или node».** Поставь любой из них —
без них не работают ни скрипты, ни хуки-защиты.

**Сессия пишет «коммит прямо в ветку main запрещён».** Так и задумано: работа идёт в ветке
задачи. Скажи «возьми задачу #N» — плагин сам создаст ветку и рабочую копию.

**Хочу свои названия меток.** В `.claude/github-tasks.json`, раздел `labels`, сопоставь
статусы со своими метками — настройка сама предложит это, если увидит похожие.
