# Приёмка задачи

Процесс — `${CLAUDE_PLUGIN_ROOT}/PROCESS.md`, раздел «Приёмка». Скрипты —
`S=${CLAUDE_PLUGIN_ROOT}/scripts`.

Аргумент — номер задачи. Нет номера — спроси.

## 1. Независимость

- Если эта сессия писала реализацию задачи N — свою работу не принимай. Скажи человеку
  открыть новую сессию и вызвать приёмку там (или запустить полный цикл скиллом `cycle`,
  где приёмщик — отдельный агент).
- Найди PR задачи: `gh pr list --head issue-N --state open --json number,url`. Нет
  открытого PR — приёмки нет: скажи, на каком шаге задача, и остановись.

## 2. Приёмщик

Запусти агента-приёмщика плагина (`github-tasks:reviewer`) с заданием: номер задачи N,
номер PR P, требование проверить по разделу «Приёмка» из `PROCESS.md` и опубликовать
вердикт одним комментарием в PR. Он работает только на чтение — хук плагина не даст ему
править файлы.

Если агент недоступен — проведи приёмку сам по тем же правилам, но только в сессии,
которая не писала реализацию.

## 3. По вердикту

Прочитай последний вердикт в PR (`gh pr view P --comments`).

- **«Вердикт: Принято»** → `bash $S/merge.sh P`. Скрипт сливает PR, закрывает задачу и
  удаляет ветку `issue-N`. Отказ скрипта — назови причину человеку, руками в обход не
  сливай.
- **«Вердикт: Возврат»** → задача остаётся открытой со статусом `in-review`; исполнитель,
  получив возврат, сам переводит её в работу (см. скилл `task-do`, «Возврат с приёмки»).
  Скажи человеку, что вернулось и кому продолжать.

Пункты, которые приёмщик отнёс к ручной проверке человеком, перечисли отдельным
коротким списком: что сделать, что должно получиться.

## Отчёт

Первой строкой: `Вердикт: Принято — PR слит, задача закрыта` или `Вердикт: Возврат —
задача у исполнителя`. Дальше — закрытые критерии, непроверенное, ручная проверка.
