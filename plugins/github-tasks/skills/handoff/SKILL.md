name: handoff
description: Используй, когда просят «передай задачу», «сохрани состояние», «закругляемся», «заканчиваем сессию», «handoff» в проекте с процессом github-tasks, или когда сессия подходит к пределу и работу по задаче продолжит другая сессия. Сохраняет состояние задачи там, где его найдёт следующая сессия: комментарий в задаче, коммит своих файлов, push. Передача не завершена, пока push не прошёл. НЕ используй для отдачи готовой работы на приёмку (это скилл task-do, шаг «Отдать на приёмку»).
---

# Передача задачи

Память между сессиями — только задача на GitHub и ветка `issue-N`. Отдельных файлов-
передач не заводим: их никто не найдёт. Процесс — `${CLAUDE_PLUGIN_ROOT}/PROCESS.md`.

## Шаги

1. **Что за задача и где работа.** Номер задачи этой сессии; рабочая копия
   `.claude/worktrees/issue-N/`. `git -C <копия> status --short --branch` и последние
   коммиты. Отдели изменения задачи от посторонних — посторонние не трогай.
2. **Закоммить своё.** Незакоммиченные файлы задачи — поимённо. Работа не доделана или
   сломана — так и напиши в заголовке коммита («незавершено: …»), не выдавай за готовое.
3. **Отправь.** `git -C <копия> push -u origin issue-N`. Отклонено из-за новых коммитов —
   `git -C <копия> pull --rebase`, разреши конфликты, отправь снова. Force push запрещён.
   Push не прошёл — передача не завершена: назови ошибку человеку.
4. **Комментарий в задачу** (`gh issue comment N --body-file ...`):
   - что сделано в этой сессии — по пунктам «Что нужно сделать»;
   - чем проверено — команда → результат; что не проверено;
   - следующий шаг — одно конкретное действие;
   - открытые вопросы и принятые по ходу решения с причинами;
   - коммит, на котором остановились.
5. **Статус.** Работа продолжится этой же или следующей сессией — `in-progress` остаётся.
   Сессия бросает задачу и продолжать некому — освободи: `bash
   "${CLAUDE_PLUGIN_ROOT}/scripts/status.sh" N ready` (снимет исполнителя и заявки;
   ветка и коммиты сохранятся для следующего исполнителя). Упёрлись в решение человека —
   `owner_decision`, во внешнее событие — `blocked`, причина — в комментарии.
6. **Проверь** `git -C <копия> status --short --branch`: ветка не впереди `origin`,
   незакоммиченными остались только посторонние файлы, которые ты явно назвал.

## Отчёт человеку — четыре строки

Где остановились (задача, коммит, push подтверждён); что дальше; готовая фраза для
следующей сессии («продолжи задачу #N»); что нужно от человека. Если push не прошёл —
вместо подтверждения ошибка.
