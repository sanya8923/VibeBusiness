name: cycle
description: Используй, когда просят «проведи задачу #N целиком», «сделай и прими #N», «полный цикл #N», «cycle #N» в проекте с процессом github-tasks. Ведёт одну задачу в одном чате от захвата до слияния: исполнение, независимая приёмка отдельным агентом (один приёмщик на всю задачу, возвраты уходят ему же), исправления, слияние, передача. Следующую задачу сам не начинает. НЕ используй, если задача ещё не поставлена (сначала task-new), и НЕ используй для приёмки чужой работы (это review).

# Полный цикл одной задачи

Процесс — `${CLAUDE_PLUGIN_ROOT}/PROCESS.md`. Скрипты — `S=${CLAUDE_PLUGIN_ROOT}/scripts`.
Аргумент — номер задачи. Нет номера — спроси, сам не выбирай.

## 1. Исполнение

Выполни шаги 1–3 скилла `task-do`: захват, подтверждение плана человеком, работа в
рабочей копии, проверки, коммит своих файлов, PR со статусом `in-review`.

## 2. Один раз согласовать план приёмки

Перед первой приёмкой — короткий список человеку: какие пункты приёмщик проверит
запуском и чтением кода; что останется ручной проверкой человека; какие файлы и коммиты
входят в границу. Дождись подтверждения. При повторных приёмках той же задачи
согласовывать заново не нужно, если критерии не изменились.

## 3. Приёмка — один приёмщик на всю задачу

Запусти **одного** агента-приёмщика (`github-tasks:reviewer`) с номером задачи и PR и
сохрани его идентификатор до конца цикла.

- **«Вердикт: Принято»** → `bash $S/merge.sh P` → переходи к передаче.
- **«Вердикт: Возврат»** → `bash $S/status.sh N in_progress`, исправь только
  перечисленное, проверь заново, коммит, `bash $S/open-pr.sh N <отчёт>`, и отдай работу
  **тому же** приёмщику через SendMessage по сохранённому идентификатору. Новым агентом не
  подменяй: пропадёт история замечаний.
- Повторяй до «Принято» или настоящего блокера.
- Замечание меняет саму задачу — не исправляй молча: остановись и уточни задачу через
  `task-new`.
- Приёмщик безвозвратно недоступен — скажи это человеку как блокер и остановись. Нового
  без решения человека не запускай.

## 4. Передача

После слияния — скилл `handoff` в короткой форме: в задаче итог, push подтверждён (ветка
задачи удалена скриптом слияния — это нормально).

## Отчёт человеку

1. номер и итог задачи; сколько было возвратов;
2. что принято проверкой, что ушло на ручную проверку;
3. следующая задача — только назвать (`task-do M` / `cycle M`), не начинать: новый вызов —
   осознанная граница работы.
