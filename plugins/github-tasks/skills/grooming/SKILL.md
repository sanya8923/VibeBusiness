# Груминг очереди задач

Работа со списком задач, а не с кодом. Процесс — `${CLAUDE_PLUGIN_ROOT}/PROCESS.md`.
Аргумент — что изменилось: находка, срез времени, смена приоритета (можно пусто).

## 1. Факты

- Открытые задачи с метками, вехами и зависимостями:
  `gh issue list --state open --limit 500 --json number,title,labels,milestone,body`.
- Закрытые за доступный период: `gh issue list --state closed --limit 500 --json
  number,title,closedAt,createdAt,milestone`.
- Цель этапа — описание вехи (`gh api repos/{owner}/{repo}/milestones`) или то, что назвал
  человек.

## 2. Скорость — только из истории

Сколько задач закрыто в неделю за последние 2–4 недели (по `closedAt`); сколько в среднем
задача проходит от `in-progress` до закрытия, если это видно по событиям. Посчитай
кодом, не в уме. Истории мало — так и скажи: «данных на N задач, скорость не
оценивается». Чисел, которых нет в истории, не придумывай.

## 3. Проект решения — показать и дождаться одобрения

Первой строкой — сходится ли объём с целью этапа при текущей скорости. Не сходится —
скажи прямо и предложи, что сократить, с последствиями.

Три списка:
- **делаем** — порядок, зависимости, веха;
- **режем** — что убираем и какой риск остаётся;
- **переносим** — что уходит в следующую веху.

Отдельно: задачи-дубли; задачи без проверяемого «Когда считаем готовым»; задачи, которые
не делаются за одну сессию (предложи, как разрезать); задачи в `in-progress`, где давно
нет коммитов (возможно брошены — решает человек).

До явного одобрения ничего не меняй.

## 4. После одобрения

- Метки, вехи, приоритеты — `gh issue edit`; статус — только через
  `bash ${CLAUDE_PLUGIN_ROOT}/scripts/status.sh`.
- Дубли закрыть с комментарием «дубль #M» и причиной; содержательную задачу без
  комментария не закрывать.
- Крупные — разрезать (новые задачи через `task-new`, старую — закрыть со ссылками).
- Устаревший текст задачи обновить: устаревшая постановка хуже отсутствующей.
- Историю не удалять.

## Отчёт — до 20 строк

Скорость; три списка; что изменено на GitHub (номера); вывод по объёму.
