# Проверка перед релизом

Механика — `bash ${CLAUDE_PLUGIN_ROOT}/scripts/release-check.sh [веха]`. Скрипт печатает
отчёт по каждой проверке и последней строкой вердикт; код выхода 0 — можно, 1 — нельзя.

## Шаги

1. **Веха.** Если человек назвал веху (milestone) — передай её скрипту. Не назвал —
   скрипт проверяет ближайшую открытую веху; вех нет — проверка задач вехи пропускается и
   это видно в отчёте.
2. **Запусти скрипт** из корня репозитория и прочитай отчёт целиком.
3. **Общие проверки** (делает скрипт):
   - все задачи вехи закрыты;
   - нет открытых задач с меткой блокера;
   - последний прогон CI на базовой ветке зелёный (если CI в проекте есть);
   - с прошлого релиза (последнего тега) в изменения не попали похожие на секреты строки;
   - список изменений — слитые PR с прошлого тега.
4. **Проверки проекта** — поле `release_checks` в `.claude/github-tasks.json`: команды
   запускаются скриптом, каждая — «пройдено / не пройдено» с выводом.
5. **Непроверяемое** (то, что требует учётной записи или устройства человека) — оформи
   отдельным коротким списком для человека: что сделать, что должно получиться.

## Ответ

Первой строкой — однозначно: `Можно выкладывать.` или `Нельзя выкладывать: <что мешает>`.
Дальше — таблица проверок со статусом, список изменений, ручные пункты для человека.
Ничего не выкладывай, не ставь теги и не сливай PR.
