# Постановка задачи

Задачу будет выполнять другая сессия, которая не видела этого разговора. Поэтому задача
обязана быть самодостаточной: цель, границы, проверяемый итог, все закрытые решения.
Процесс — `${CLAUDE_PLUGIN_ROOT}/PROCESS.md`, шаблон — `${CLAUDE_PLUGIN_ROOT}/templates/task.md`.

Аргумент: замысел своими словами; если первым идёт номер — уточняется существующая задача.

## 1. Разведка — до единой строки задачи

Запусти агента-разведчика плагина (`github-tasks:scout`) с замыслом. Он вернёт дубли,
затронутый код, зависимости и развилки. Если агент недоступен — сделай то же сам:

- **Дубли:** выгрузи заголовки всех задач и ищи совпадения сам —
  `gh issue list --state all --limit 500 --json number,title,state`. Поиск GitHub плохо
  берёт словоформы и молча возвращает пусто. Нашлась близкая задача — предложи дополнить
  её комментарием, а не заводить вторую.
- **Затронутый код и зависимости** — только чтобы определить границы, а не проектировать
  реализацию заново.

## 2. План — показать человеку и дождаться одобрения

Одним сообщением: цель; что сделать (проверяемые пункты); когда считаем готовым
(наблюдаемый признак, проверяемый посторонним за минуту); что не входит; зависимости;
развилки — каждая с вариантами, ценой и твоей рекомендацией. Существенные развилки
закрой до создания задачи — не оставляй их исполнителю.

До явного одобрения задачу не создавай и не меняй. Человек поправил — обнови план и снова
дождись одобрения.

## 3. Размер

Одна задача — одно изменение, которое выкатывается отдельно, и одна сессия работы.
Появилось «и заодно» — это две задачи. Крупное — режь на несколько задач со строкой
«Зависит от: #N» и общей вехой (milestone).

## 4. Задача

- Тело — по шаблону: «О чём это», «Что нужно сделать», «Когда считаем готовым»,
  «Состояние и зависимости» (обязательно «Не входит»), «Ссылки».
- Дополнительные правила проекта — поле `task_rules` в `.claude/github-tasks.json`;
  прочитай и соблюдай.
- Проверь перед записью: нет ссылок на решения «из чата», которых нет в тексте; промпт не
  оставляет исполнителю уже закрытые решения.
- Заголовок — что сделать, в повелительном наклонении, до 72 знаков.
- Создай: `gh issue create --title ... --body-file ...`; метка статуса — `ready`, если
  постановка полная, или `owner_decision`, если в «Состоянии» остался «Не решено»
  (имена меток — из файла настроек). Приоритет `P0`–`P3` и веха — если человек назвал.
- Уточнение существующей задачи — `gh issue edit N --body-file ...` и комментарий, что
  изменилось.

## 5. Отчёт

Номер и ссылка; место в очереди (от чего зависит, что блокирует). Если задача конкурирует
за приоритет с уже взятой работой — скажи прямо, что придётся подвинуть.

## Чего не делать

- Не начинать выполнение — даже «маленькую часть».
- Не ставить метку `in-progress` и не назначать исполнителя.
- Не заводить задачу на то, что дешевле сделать прямо сейчас руками, и на наблюдение без
  действия («выглядит старомодно») — у такой задачи нет проверяемого итога.
- Не обещать сроки в часах точнее «час / полдня / день и больше».
