# Обработка ошибок в n8n: Error Trigger + AI-самолечение

Готовые воркфлоу к ролику **[«Все ноды n8n: Error Trigger + AI-агент для исправления ошибок»](https://www.youtube.com/watch?v=4YG7QkBXHcs)** (канал [Vibe Business](https://www.youtube.com/@vibe_business)).

Показывают, как в любой сценарий добавить обработку ошибок: логировать сбой, слать алерт в Telegram, переключаться на резервный источник и даже чинить workflow автоматически через AI-агента.

> Если пригодилось — поставьте ⭐ репозиторию.

## Что внутри

| Файл | Что делает |
|------|-----------|
| `workflows/1-execute-error-workflow.json` | **Генератор ошибки.** По расписанию бьёт в несуществующий адрес и падает — чтобы было что обрабатывать. Внутри же резервная ветка. |
| `workflows/2-error-workflow.json` | **Обработчик.** `Error Trigger` ловит падение и расходится на 4 ветки: лог → алерт → резерв → самолечение. |

Оба воркфлоу протестированы на seed-данных: поток данных, все выражения и сборка файла с логом ошибки отрабатывают корректно.

## Как запустить

1. **Импорт.** В n8n: `⋯ → Import from File` — залейте оба JSON.
2. **Подключите креды** (нод-заготовки идут с плейсхолдерами):
   - **Telegram** — токен бота, а `chatId` замените с `YOUR_TELEGRAM_CHAT_ID` на свой (узнать — у `@get_id_bot`).
   - **OpenAI** — ключ для ноды «Анализатор логов (GPT)».
   - **Google Docs** — OAuth-креды и `YOUR_GOOGLE_DOC_URL` (создайте пустой документ Logs, дайте доступ по ссылке).
3. **Свяжите воркфлоу.** В генераторе: `⋯ → Settings → Error Workflow` → выберите «Error Workflow (обработка ошибок)». **Без этого падение не уйдёт в обработчик** — это ключевой шаг.
4. В обработчике в ноде «Запустить резервный сценарий» перевыберите импортированный генератор из списка.
5. Активируйте генератор и ждите — раз в 15 секунд он падает, обработчик ловит.

## Четыре ветки обработчика

- **Лог** → запись сбоя в Google Docs (можно заменить на БД / Grafana / S3).
- **Алерт** → нейронка описывает проблему по-русски, в Telegram уходит текст + файл со всем JSON ошибки.
- **Резерв** → `Execute Sub-workflow` берёт данные с запасного сервера, пока основной лежит.
- **Самолечение** → POST отдаёт JSON ошибки внешнему AI-агенту, который через [n8n MCP](https://github.com/czlonkowski/n8n-mcp) чинит инстанс (в демо — меняет битый адрес в HTTP-ноде).

## Про AI-агента (ветка самолечения)

Сам сервер-агент — **отдельная программа** (мини-обёртка над Gemini CLI + n8n MCP), в n8n она не собирается. В воркфлоу есть только нода-отправитель `Отправить ошибку AI-агенту` (HTTP POST). Замените `https://your-self-healing-server.example.com/webhook/error` на адрес своего сервиса.

## Заметки по нодам

- **Error Trigger** отдаёт два объекта: `execution` (данные запуска + `error.stack`) и `workflow` (id и название упавшего сценария).
- **Manual Trigger** для Error Trigger бесполезен — он не имитирует реальное падение (показано в ролике).
- В ноде «JSON ошибки в файл» **Set стоит перед Convert to File специально**: нода умеет читать только предыдущую ноду.
